## Specs

**S1 — R4-HeaderScanWindow (WARNING).** Exact issue text: "`crates/webfang_core/src/infrastructure/export/vector_exporter_header.rs:13-14` | Fixed `HEADER_SCAN_BYTES = 512` assumes the metadata header never exceeds 512 bytes; a larger header makes `read_header_bytes` truncate and `find_subslice` miss the markers, so append fails with \"header is missing the field\" instead of handling a bigger header." Verified: `build_header_line` interpolates `created_at` unvalidated; the legacy-migration path copies it from an external file. Authorized scope: reject an oversized `created_at` at header construction with a typed error; regression test. No format change for valid inputs.

**S2 — R4-NoFsyncOnWrite (WARNING).** Exact issue text: "`crates/webfang_core/src/infrastructure/export/record_store_file.rs:47-53` | `RealFs::write` only flushes to the OS page cache (no `fsync`); on power loss, data written after the atomic rename commit point can be lost, leaving a state file that `load_or_init` quarantines and replaces with a fresh store. Documented as by-contract." Verified: `StoreFs::write` documents "NO fsync by contract"; `record_store.rs` module doc already states process-crash (not power-loss) durability is the contract. Disposition: (b) accept as documented constraint in `docs/adr/0023-...md` with rationale. No code change.

**S3 — R4-AppendCrashRecoveryGap (WARNING).** Exact issue text: "`crates/webfang_core/src/infrastructure/export/vector_exporter_header.rs:68-95` | Append mode has no automatic recovery if the process crashes mid-document write: a partial document leaves invalid JSON; later appends parse the header but fail to locate the insertion point. The SIGKILL integration harness covers the flow; unit tests do not." Parent spot check found a stronger failure: `VectorExporter::writer` only truncates when a `]` exists in the last 256 bytes; with a torn document there is no `]`, `read_append_state` never parses document lines, and `close_json` appends `]}` — silent corruption. Authorized scope: fail closed with a typed `ExporterError::WriteError` + structured warning and leave bytes untouched; regression test. Automatic vector torn-tail truncation is explicitly out of scope and documented in the ADR.

**S4 — R4-LockSentinelWorldReadable (SUGGESTION).** Exact issue text: "`crates/webfang_core/src/infrastructure/export/record_store_file.rs:78-85` | The `<state>.lock` sentinel is created with default permissions (0o644) and contains the owning PID. On shared systems this leaks process identity; the lock is advisory on Unix and the PID is diagnostic-only." Authorized scope: create the sentinel with `0o600` on Unix and tighten pre-existing sentinels; no change to lock semantics; regression test. Rust std docs consulted: `OpenOptionsExt::mode` sets creation bits (default 0o666 masked by umask), `PermissionsExt` tightens existing files. No `cfg(windows)` arm added.

**S5 — R4-MigrationBackupTimestampCollision (SUGGESTION).** Exact issue text: "`crates/webfang_core/src/infrastructure/export/record_store_file.rs:147-153` | v1→v2 backup filenames use millisecond precision, so two migrations in the same millisecond could collide. Prevented in practice by the store lock serializing migrations." Authorized scope: reuse the existing monotonic per-process nonce (`RecordStore::tmp_path`) for the `.v1.bak.` suffix; regression test. No reader of the suffix exists in code; ADR-0014 prose only.

**Acceptance criterion (verbatim, issue #3000):** "Each item is either (a) fixed with a regression test, or (b) explicitly accepted as a documented constraint with rationale in `docs/adr/` or the baseline `notes`. No item reopens review on PR #2998."

**Out of scope:** fsync/`sync_all` in `RealFs::write`; automatic recovery of a torn vector document; changing the on-disk header layout; reopening review on PR #2998.
