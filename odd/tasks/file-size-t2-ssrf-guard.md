## Specs

Las S1–S13 de `file-size-t2.md` aplican íntegras. M2 añade:

**S14 — Censo pre-corte de los privados que tocan los tests (S8 aplicado a visibilidad).** "Qué privados llaman los tests. En `error.rs` la medición mostró que ningún test tocaba los helpers privados, y por eso PR B y PR C no necesitaron visibilidad nueva. Aquí lo esperable es lo contrario: los tests de IP y de literales llamarán directamente a `is_forbidden_ip`, `parse_ipv4_all_forms`, etc." El censo se hace en este worktree ANTES del primer corte de PR A y se registra en el Log: para cada ítem de la región de producción, ¿aparece referenciado en la región de tests (línea > 1132)?

**S15 — Re-parentar, nunca ensanchar (refuerza S5).** "Cuando PR B mueva el bloque IP a `ssrf_guard/classification.rs`, esos ítems quedarán privados de `classification` y los tests, hijos de `ssrf_guard`, dejarán de verlos." La solución es re-parentar los módulos de test como hijos del módulo destino (el `#[path]` se re-apunta, el texto del test no cambia): "Decide eso ahora y nombra los archivos de PR A pensando en ese destino (`tests_ip_*` separados de `tests_literals`, `tests_redirect`, etc.). Prefiero re-parentar a ensanchar." Diff de modificadores de visibilidad vacío en PR B y PR C (compuerta C11).

**S16 — Estado compartido único entre archivos de test.** "Los tests del guard SSRF suelen tocar variables de entorno (`DISABLE_ENTRY_GUARD_ENV` y los hatches) y el registro `OnceLock`. Busca un `Mutex` estático, un `serial_test` o helpers locales dentro de `mod tests`. Si los tests parten en varios archivos, ese helper tiene que vivir en un módulo común (`tests_support`) visible a todos, y no duplicarse: dos mutexes distintos significarían que los tests dejan de serializarse y fallan de forma intermitente, algo que ni `--list` ni una sola corrida detectan. Corre la suite del módulo varias veces con `--test-threads` altos antes de dar por buena la partición."

**S17 — Paridad junta y última (refuerza S11).** "Son los que existen para detectar deriva entre el guard y la capa de dial (`seed_guard_refusal_agrees_with_the_enforcing_guard`, `the_dial_layer_always_denied_set_covers_every_never_allowable_range`). Van a un único archivo que vea ambos lados, como dice S11, y ese archivo es el último en moverse si algo se re-parenta."

**S18 — PR B: verbatim absoluto con recuento por nombre.** "las tres rutas de veredicto deben coincidir y Teredo se evalúa antes que las encapsulaciones" — "añade a la prueba verbatim un recuento de las tres rutas por nombre antes y después, y mueve el bloque sin reordenar nada, `parse_ipv4_all_forms` y `parse_ipv4_number` incluidos, porque son IP pura y quedaban fuera del rango 188–740 en el primer esbozo. Con 70 importadores, las `pub use` de `ssrf_guard.rs` deben dejar intactas todas las rutas públicas, y la compuerta es `cargo check --workspace --all-targets --all-features`."

**S19 — Parar antes de mover.** "Cuando tengas la medición de esos privados y del estado compartido, me la pasas y fijamos la partición de PR A antes de mover nada."
